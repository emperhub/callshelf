# Linux CLI Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a native Linux CLI for checking WARP status and rotating the egress IP.

**Architecture:** Add an executable Bash entry point that uses the installed `warp-cli` and `curl`, preserving the existing PowerShell implementation and Windows GUI. Test it with stub executables and document Linux setup and usage.

**Tech Stack:** Bash, system `warp-cli`, `curl`; shell test harness with mocked commands.

**Spec:** `docs/superpowers/specs/2026-11-14-linux-cli-design.md`

## Global Constraints

- Use Bash with the system `warp-cli` and `curl`; do not change the existing Windows PowerShell or GUI behavior.
- Keep Linux GUI support, dependency installation, and packaging out of scope.

## Review Focus

- `warp-cli` or `curl` is missing: print an actionable error to stderr and exit nonzero.
- An unknown option or invalid/nonpositive numeric timeout/retry value is supplied: reject it before invoking WARP.
- WARP returns an error or an unrecognized status: report failure without printing success-shaped output.
- The registration is managed: refuse rotation before disconnecting or deleting the registration.
- A rotation/probe fails after disconnect: attempt to reconnect WARP and return a nonzero result.
